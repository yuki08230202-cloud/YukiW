# クライアント情報の整理(企画の前工程)

## 目的
求人用ショート動画の企画書を作る前に、クライアントの事実を一か所にまとめる。台本の数字や言い方は、すべてここから取る。業種は決め打ちしない。

## もらう資料
`clients/<社名>/inbox.md` に、ユーザーが貼る。求人媒体のURL、HP、会社案内や求人票のPDF、これまでのやりとり。
URLはWebFetchで読む。読めないページ(ログインがいる、強いブロックがある)は、空振りを繰り返さず、本文を貼ってもらう。

## 手順
1. どの職種を募集するかを確認する。職種が複数あるときは、職種ごとに事実の表を分ける(例: 営業職、ドライバー、アルバイトでは、条件も伝える相手も違う)。
2. 資料から次を表にする。資料にない項目は「記載なし」にする。推測で埋めない。各行に出典(どの資料か)をつける。
   - 会社: 社名、事業内容、拠点、規模
   - 仕事: 仕事内容、一日の流れ、必要な免許・資格、未経験の可否
   - 条件: 給与(基本給、手当、実績の幅)、勤務時間、休日、残業、待遇・福利厚生、研修
   - 募集の選考: 応募方法、見学や面接の流れ
   - 職種ごとの項目(例。資料にあるものを優先): ドライバーなら免許区分、車種、運ぶもの、エリア、泊まりの有無、荷役の有無。営業なら新規かルートか、ノルマ、インセンティブ、転勤。アルバイトなら時給、シフト、週何日か、学生可か、扶養、服装
3. 資料の中で食い違う記載を探す。見つけたら一覧にして、どちらで言うかをクライアントに聞く項目に入れる。
4. 動画で言うと誤解を招く項目を探す。例: 「ノルマなし」「未経験OK」「高収入」「誰でも」。年齢や性別で限る言い方、給与を盛った言い方は避け、求人票の範囲にとどめる。
5. これまでの投稿や他社の動画の情報があれば、参考として一緒に整理する。

## クライアントに聞くこと(標準)
- 撮影の準備: 出演者、撮影日と時間帯、撮影場所と撮影してよい範囲、社員や社外の人を映せるか、車両や設備の撮影可否、出演する人の同意
- 言い方と数字: 食い違いの確定、給与の数字を出してよいか、誤解を招く言い方の確認
- 進め方: 最初に撮る企画、投稿予定日と投稿アカウント、参考動画を載せてよいか、契約の総本数

## 出力
- 事実の表(職種ごと)と、食い違いの一覧を、チャットで返す。
- クライアントに聞く項目を、番号つきの短いリストで返す。ミーティング前に読める長さにする。
- 事実の表は `clients/<社名>/facts.md` に保存する。

## 守ること
- 数字と条件は、資料にあるものだけを使う。
- 日本語はやさしく、短くする。AIっぽい言い回しを避ける。
